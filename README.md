# DADGAD Transposer

**Same chords, new shapes.** Type a song's chord progression in standard tuning — get open, drone-friendly DADGAD voicings back.

No backend. No account. Works offline once loaded.

---

## What it does

| Input | Output |
|---|---|
| `D Dsus4 G Em7 Cadd9 Asus4` | SVG chord diagrams ranked by how well they use open D/A drones |

The chord **names** don't change between tunings. The **shapes** do. This tool searches the DADGAD fretboard (D A D G A D) for the most playable voicings that favor open-string drones and low positions.

## Architecture

```
dadgad-transposer/
├── packages/
│   └── core/            # Domain logic — zero UI dependencies
│       ├── src/
│       │   ├── types.ts      # Pitch classes, chord qualities, interfaces
│       │   ├── parser.ts     # parseChord(), parseChordSequence()
│       │   ├── voicing.ts    # findVoicings(), getFretWindow()
│       │   └── index.ts      # Public API surface
│       └── package.json
│
├── apps/
│   └── web/             # React + TypeScript + Vite + PWA
│       ├── src/
│       │   ├── App.tsx          # Main UI (input, controls, results)
│       │   ├── main.tsx         # Entry point
│       │   ├── theme.ts         # Luthier palette (walnut, brass, bone)
│       │   └── components/
│       │       ├── Diagram.tsx  # SVG chord diagram renderer
│       │       └── ChordCard.tsx # Card wrapper with voicings
│       ├── index.html
│       ├── vite.config.ts       # React + PWA plugin
│       └── package.json
│
├── dadgad.html          # Original prototype (vanilla JS) — preserved for reference
├── dadgad-chords.jsx    # Original prototype (React JSX) — preserved for reference
├── package.json         # Workspace root
└── README.md
```

**Key decision:** `@dadgad/core` has **zero UI dependencies**. It's pure TypeScript — types, parsing, and the voicing search algorithm. The web app imports it like any library. This means the engine could later power a CLI, a mobile app, or a different UI without touching domain logic.

## Offline / PWA goal

The app should work **fully offline** after the first load:

- **Service worker**: Generated by `vite-plugin-pwa` with Workbox. Strategy: `autoUpdate` — new versions install in the background and activate on next navigation.
- **Assets cached**: All JS, CSS, HTML, fonts, and icons.
- **No network calls**: The app has no API. Everything runs client-side.
